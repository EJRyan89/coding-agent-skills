# Setting up a machine

This page walks a new Windows machine from nothing to a deployed and verified installation that can also run validation, in the order that avoids rework: each step needs only the ones before it. Each step names what installs the tool and the check that shows it worked, and beside it the Windows condition a fresh install meets there, as what happens and what to do. [Installation](installation.md) owns the deployer's requirements and the install commands for each tool, and [Development environment](../CONTRIBUTING.md#development-environment) the tools only validation needs; this page puts them in order. On Linux, [Validating on Linux](../CONTRIBUTING.md#validating-on-linux) and [On Linux](installation.md#on-linux) cover the same ground, and none of the Windows conditions below applies.

1. **Git for Windows and the GitHub CLI.** Install both from the [Windows table](installation.md#on-windows), sign in with `gh auth login`, and [get the source](../CONTRIBUTING.md#getting-the-source). `git --version` and `gh auth status` show that it worked.
   - A shell started before an install keeps the `PATH` it started with, so it, and `python deploy.py check` run from it, report the tool just installed as missing. Open a new terminal after every install on this page, and quit and restart an editor or agent application that was already running, as [After installing](installation.md#after-installing) explains.
   - With the GitHub account's email address kept private, GitHub refuses a push whose commits carry the real address, and every commit made with it has to be re-authored. Before the first commit, set git's address to the noreply one GitHub shows under **Settings > Emails**, with `git config --global user.email '<id>+<user>@users.noreply.github.com'`; `git config user.email` shows it.
2. **Python.** Install it from the [Windows table](installation.md#on-windows), then turn off the `python.exe` and `python3.exe` app execution aliases, as [Codex CLI settings](installation.md#codex-cli-settings) describes. `python deploy.py check`, run from the clone, shows that it worked: its `python command` line is `FOUND` with your Python installation.
   - Every Windows install registers those aliases, and Codex's sandbox cannot start them, so every skill script fails under Codex while they are on. Turn them off whichever Python installer you used, and keep `py` and `pymanager` on if they are listed; [Python app execution aliases](codex-support.md#python-app-execution-aliases) says why reordering `PATH` is not enough.
3. **PowerShell 7 and PSScriptAnalyzer.** Install PowerShell's MSI build with `winget install --id Microsoft.PowerShell --installer-type wix`, then install PSScriptAnalyzer as [Development environment](../CONTRIBUTING.md#development-environment) shows. `python deploy.py check` shows that it worked: its `pwsh command` line is `FOUND` with the `pwsh` in PowerShell's own folder under `C:\Program Files\PowerShell`. `pwsh -NoProfile -Command 'Get-Module -ListAvailable PSScriptAnalyzer'` lists the module.
   - WinGet installs the packaged (MSIX) PowerShell unless told otherwise, and its `pwsh` is an app execution alias that no Codex sandbox can start, so every command Codex runs fails before it starts. Install the MSI build with the flag above; a machine that already has the packaged one uninstalls it first, as [PowerShell app execution alias](codex-support.md#powershell-app-execution-alias) shows, and `check` reports the `pwsh command` line `UNUSABLE` until then.
4. **ShellCheck and the development dependencies.** Install ShellCheck from the [Windows table](installation.md#on-windows), and the pinned `ruff`, `mypy`, and `pytest` into the Python that runs validation as [Development environment](../CONTRIBUTING.md#development-environment) shows. `shellcheck --version`, `python -m ruff --version`, `python -m mypy --version`, and `python -m pytest --version` show that they worked.
5. **The runtimes you use.** Install Claude Code, Codex CLI, and GitHub Copilot CLI from the [Windows table](installation.md#on-windows); none is needed to deploy. For Codex, add the Windows sandbox setting to `~/.codex/config.toml` as [Windows sandbox mode](codex-support.md#windows-sandbox-mode) shows. `python deploy.py check` lists each runtime with its version, and its `codex sandbox` line is `FOUND` once the setting is read.
   - Codex's elevated Windows sandbox stores credentials bound to the machine that set it up, so a `~/.codex` folder copied from another machine fails with a decryption error on every command. Run `codex sandbox setup --elevated --current-user` on each machine, which asks for an administrator's approval once, including after copying the folder.
6. **The .NET SDK and dotnet-format**, for the opt-in `dotnet` bundle. Install the .NET SDK from [Microsoft's download page](https://dotnet.microsoft.com/download) at or above its floor in [Dependency updates](dependency-updates.md#runtime-tool-floors), and the deprecated global tool with `dotnet tool install --global dotnet-format`, which only a solution older than SDK-style needs, as [.NET skills](dotnet.md#requirements) explains. `python deploy.py check` shows that they worked: its `dotnet` and `dotnet-format` lines name the versions it found. `check` marks a tool `OPTIONAL` when no skill the deployment requests needs it, installed or not, so both lines read `OPTIONAL` until a deployment requests the `dotnet` bundle, and `dotnet-format`'s stays so; a tool it cannot find reads `not installed` instead of a version.
7. **A PDF tool**, for reviewing a PDF a pull request changes. Install `pdftotext` from the Xpdf command-line tools or Poppler at or above its provider's floor, and put its folder on `PATH`, as [Requirements](installation.md#requirements) describes. `python deploy.py check` shows that it worked: its `pdftotext` line is `OPTIONAL` with the version it found, since every skill that reads a PDF declares the tool optional, naming any older copy, such as the one Git bundles, that it passed over.
8. **Check, deploy, and verify.** `python deploy.py check` now reports every tool the deployment needs `FOUND`, and each optional tool you installed `OPTIONAL` with its version rather than `not installed`. Then configure, preview, and deploy from the clone as [Deploying](installation.md#deploying) shows, and run `python deploy.py verify`, which reports every adapter `FOUND` for Codex and Copilot.
9. **Confirm that Codex's sandbox starts a command**, without starting a model, from any folder: `codex sandbox --include-managed-config --permission-profile :workspace -- pwsh -NoProfile -Command 1+1` prints `2`. `check`'s `codex sandbox` line reports only the configured mode, so this is the step that shows the sandbox, the MSI PowerShell, and the machine's own sandbox setup work together; a failure names what could not start, as [Windows sandbox mode](codex-support.md#windows-sandbox-mode) explains.
